# ui-main —— 主界面的主程序和主样式（2026-10-21 从 ui.html 拆出来）

以前主界面是一个 2.26 万行的 `ui.html`：一整段内联 `<script>`（约 1.86 万行）+ 一整段 `<style>`（约 3000 行），改起来很难找。
现在拆成了按功能分的文件，`ui.html` 只剩约 1100 行（页面骨架 + 各个脚本的加载顺序）。

## 怎么改

| 要改 | 改哪里 | 改完要做 |
|---|---|---|
| 主程序（JS） | `ui-main/01-base.js` … `ui-main/21-boot.js` | **跑一下 `node scripts/build-ui-main.cjs`**，把它们拼成 `ui-pure/ui-main.js` |
| 主样式（CSS） | `ui-main/css/01-base.css` … `08-prompt-input.css` | 不用做什么，页面直接加载这几个文件 |

- ⚠ **别直接改 `ui-pure/ui-main.js`**：它是拼出来的，下次一拼就被盖掉。
- ⚠ **改了 JS 源文件忘了拼**：软件跑的还是旧代码。`node scripts/test-changed.cjs`（自动挑测试）和发版脚本都会检查，没拼会报红 / 拦住。
- 报错里说 `ui-main.js 第 N 行`：`node scripts/build-ui-main.cjs --where N` 告诉你是哪个源文件第几行。

## 每个文件管什么

每个文件开头都写着「管什么」。大致顺序：基础 → 核心状态 → 桥断连 / 折叠 → 任务卡 → 报错堆 → 缓存 / 预览 / 大图 → 滚轮归属 → 抠像 → AI 运行时 → 设置运行时 → 调试 / 校色 / 重跑 → 生成卡卡面 / 表单 → 性能 / 编组 / 盖印 → 开始计算 → 卡片内容 → 外挂三级 / 填充 → 各卡滚轮 → 大二级宿主 → 三级 / 预设二级 → 预设滚轮 / 参考图 / 示波器 → 启动收尾。

## 为什么 JS 要「拼成一个文件」再加载，而不是直接加载 21 个文件

因为这段代码本来是「一整段」写的，里面有不少地方依赖「一整段」的规矩：
1. 后面写的函数，前面也能直接调用（一整段里函数会被提前准备好）；
2. 加载时排进队列的「稍后执行」（then / setTimeout / await 之后的部分），要等**整段**跑完才执行 —— 那时所有东西都准备好了。

直接加载 21 个文件的话，每个文件跑完浏览器就会先执行排队的回调，那时后面的文件还没来 ⇒ 2026-10-21 实测多出 4 种错误（`tmp/split/` 里有分析工具和记录）。
拼成一个文件，浏览器眼里还是一整段，**加载行为跟拆之前完全一样**（拆完验过：8 个画面每个元素的样式 + 位置一致、加载时所有异常逐字一致）。

样式（CSS）没有这个问题，所以直接按顺序 `<link>`。

## 测试为什么还能读「ui.html 里的代码」

很多测试是读 `ui.html` 的源码文本、按标记切一段出来跑的。它们开头都加了一行
`require(…/scripts/ui-source.cjs).install()`：读 `ui.html` 时拿到的是**拼回原样**的版本（跟拆之前的 ui.html 一字不差）。
新写的测试要读 `ui.html` 内容的话，也在开头加这一行。

## 想往主程序里加新代码

加在功能最相近的那个文件里；如果是开软件时要执行的启动动作，加在 `21-boot.js`。加新文件的话：文件名 `NN-名字.js`（两位编号决定顺序），开头照抄别的文件的说明格式（最后一行 `// ── 以上是文件说明（拼进 ui-main.js 时会去掉）──` 不能少），然后跑 `node scripts/build-ui-main.cjs`。
