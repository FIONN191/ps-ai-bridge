# PS AI Bridge：V7 功能接入设计（已确认）

日期：2026-10-26。当前本地安装：桌面端/插件 0.5.5，helper 0.5.4。

## 目标与证据边界

把用户提供的修图轮椅 V7 安装包及两段教学中可核验的功能加入 PS AI Bridge；保留现有 Photoshop 工作流、历史、预设与无需 API 的专用 Chrome 通道。新增代码完成后必须重新打包、安装到当前 App 和 PS 插件并验证，不能只交源码。

本文件是接入设计，不是已完成功能清单。任何条目只有通过实际输入、执行、结果存储与回传验收后才记为完成。

- Windows 安装包 `WheelchairV7_1.9.7_x64-setup.exe`，SHA-256 `26de0c1a5348f1bc346570ae735032365aed6fb38737c93c416897da8f21a90b`。NSIS 容器静态提取 51 个文件；Tauri 主程序内连续资源表提取 326 项、全部成功 Brotli 解压，含实际 `ui.html`、前端脚本、样式与素材。
- `version.js` 和 UXP manifest 都标识 1.9.7。长视频文件名为 V7.1.9.17，画面有 1.9.16 公告；尚不能认定视频运行版本和安装包完全一致。
- 两视频实测长度 2:34:13.70 和 26:00.47。全片定间隔抽帧并补查重要位置，未逐帧观看或转写音轨，因此口述、瞬时操作和较新版私有功能仍可能遗漏。
- 静态资源中存在实现不等于真实 Windows/Photoshop/云端验收成功。视频里的配置页、失败任务、外部网页分别记录。
- 本次只读分析，不运行第三方 exe，不调用作者云端、不导入他人的登录令牌，也不把分析目录的前端和 Python 脚本直接复制进产品。

证据位置：`docs/research/wheelchair-v7/`。源提取物与帧图在 `/private/tmp/psai-v7-analysis/`，未加入 Git。REA 桥接分析父证据 `ev_6f3fc25d6a9d4c8b574d386cc989c4b8be43374b6e66b0b5c9ebe3572369281a`，只分析了所选桥接源，不代表完整原生主程序分析。原始证据导出位于该临时目录 `rea-evidence.json`。

## 接入方案选择

| 方案 | 交付方式 | 代价和限制 |
|---|---|---|
| A. 在现有架构逐模块补齐（建议） | 保留 Electron/helper/UXP，增加独立模块和统一数据层；现有 Chrome、Codex、agy 通道继续使用 | 最容易保留现有数据和回图行为，需分批验证工作流与工具 |
| B. 新建第二套工作台并共用 helper | 新工作台完整独立，旧工作台作为兼容入口 | 能独立调整布局，但会同时维护两套状态和设置，最终仍需数据合并 |
| C. 更换桌面框架与重做 PS 桥 | 重新组织整个应用，再迁移现有能力 | 范围更大，会重复实现已验证的安装、登录、更新和专用 Chrome 功能 |

推荐 A。功能对齐按实际行为和数据验收；界面继续使用用户现有的深色工作台。增加「工具」「预设管理」「项目」「幕布」「助手」入口，复杂任务在桌面端完成；PS 面板保留快速选择、生成、参考、贴回及常用工具入口。紧凑悬浮模式作为可选布局，不强制照搬原产品卡片样式。

## 数据与执行设计

1. **沿用 Node helper 为本地事实来源。** 新增独立 stores/services/routes，renderer 和 UXP 共用接口，不继续让关键业务状态分散在两个 localStorage。
2. **实体**：Connection（不嵌入导出包的密钥引用）、Preset/Revision、Asset、Job/Candidate/Variant、Run/Step/Region、Project、Canvas、AssistantSession。每类记录有 schemaVersion；写入采用临时文件+原子替换或明确的事务仓储，文件与元数据通过稳定 ID 关联。
3. **PS 桥**：扩展为明确命令（文档列表/捕获、选区读取/应用、图层/蒙版操作、结果放置），带 requestId、文档会话与原始目标。保持串行 modal 操作；关闭文档、断线、超时必须停止或等待重绑，不能随意贴到当前新文档。
4. **作业生命周期**：queued → submitting → running → downloaded → processed → awaiting-selection/placing → done；生成失败和回传失败单列。上游 taskId、幂等键先落盘；进程重启时未知提交状态进入人工核对，不盲目重新收费生成。
5. **模型适配**：通道声明模型、参考图上限、尺寸、mask、流式进度、取消和多图能力。工作流预检缺项时说明原因，不能静默跳到不等价模型。
6. **本地引擎**：单独 Python/ONNX/PyTorch 环境，按实际模型能力启用；Mac 不承诺 CUDA，Windows 不用 Mac 验收结果替代实机验证。模型未下载时不可把工具标成可用。
7. **现有数据迁移**：先备份 job.json、预设、偏好和插件状态；旧记录只补字段，不删除原图或改变原有文档。将已应用 variant 与初始生成文件明确区分。
8. **本地/云端分界**：修图与工作台默认不要求新增平台账号；Google/ChatGPT 登录继续提供网页生图。S1–S4 自建后台是否本次一并建设需要用户选择，不能把第三方平台服务视为已拥有的依赖。

## 分批施工与验收

依赖顺序：P0 → P1/P2 → P3 → P4/P5 → P6/P7；S1–S4 按确认的服务范围单独实施。这是完整范围的分批交付，不以第一批完成代替全部完成。

- 每批只把实现且验收通过的条目标为完成，并在功能矩阵记录版本和测试证据。
- P0/P1：旧预设/历史能读取；导出再导入内容、参考图与版本一致；PS 已应用版本与桌面预览一致；异形选区回贴正确。
- P2/P3：真实服务返回任务 ID；模型/参数实际映射；一项失败不影响其他项；取消不误杀其他任务；重启恢复不重复提交；分区/拼接回贴逐块对位。
- P4/P5：透明蒙版/像素尺寸正确、预览等于输出；拆光与画质增强显示真实算法/服务；节点多候选需要明确选择才流向下游。
- P6/P7：项目/布局/对话重启保留；恢复前预检；助手动作可定位原文档、停止并记录执行结果，不能把自然语言回复当动作完成。
- Mac 本机：打包后验证签名、安装文件内容、启动、真实 PS 心跳和至少一条端到端流程。更新前检查生图队列与未保存文档；安装备份到项目 `backups/`。未保存文档阻止强制 PS 重启。
- Windows：生成安装包并执行构建/契约检查，真正的快捷键、PS 桥、原生推理须 Windows 实机验收；只有打包不能标 Windows 全功能通过。
